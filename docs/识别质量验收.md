# 图片识别质量验收（2026-10-14）

本报告来自浏览器生成的虚构简历，与两张用户图片的私有验收分开。修复前实现来自 Git HEAD：`55f93233eac04c82c6a2722d38c20f4c33aa9bd0`；验收没有切换工作区。

## 条件与指标

6 种字体/版式组合，各使用原尺寸 PNG 和缩小至约 72% 的 JPEG（质量 74），共 12 组。包含单栏、双栏、18/20/22 像素正文，使用本机系统字体。最后两种紧凑版式在第一轮调试后加入，用于暴露原样例未覆盖的问题。它们现在也属于回归集，不能继续称作全新的盲测。

字符准确率忽略空白，以浏览器 DOM 文本为真值；因此 100% 不代表空格、标点与原图完全一致。字体指标按文本块的候选字体是否命中生成时指定的字体统计，不是整张图的视觉相似度。完整验收还要求字号误差中位数 ≤12%、归一化位置误差均值 ≤1.5%、无漏块和无初始溢出。字体候选命中率须 ≥65%。

## 密集正文误加粗修复（2026-10-15）

新截图显示大量普通正文被随机加粗，原有粗体前缀又有漏检。私有诊断确认：48 行、约 1694 字符的页面触发了浏览器参考字形的预算上限，精匹配被整体跳过。原回退分支仅在浏览器参考存在时做局部粗体置信度检查，缺少参考时反而放宽了推断。

修复：先用每行代表字符识别字体，再只为选中的字体生成全字符参考；所有回退都检查字体证据，缺失的浏览器字形不混入 PIL 模板；局部字重的匹配位置限制在相应字符附近。数字标签保留整体字重，不自动生成数字内部的混合粗体。空格补充完整字形的像素间隙依据，排除碎片与残缺字母。私有单次精匹配诊断约 35 秒，原图、工程和用户修改没有被覆盖。

曾试验像素误差评分和同页重复字形统计。它们在部分条件下降低误加粗，但也使真实粗体召回率或其他字体条件退化，最终撤回；没有以某张图片改善为理由保留已知跨模板退化的试验性规则。预算和回退修复属于可明确复现的共同缺陷。

旧的 8 组专项结果为 5/8 完整门槛通过，PNG 条件通过，缩放微软雅黑、宋体、等线仍未达到全部字重门槛。上一轮 6/8 不可作为本轮结论；保守回退后部分压缩条件的召回率更低。这些失败仍保留在 `artifacts/style-fidelity/corpus/report.json` 和其 `runs/`，脚本真实返回失败。
