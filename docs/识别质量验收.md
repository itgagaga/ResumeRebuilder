# 图片识别质量验收（2026-10-14）

本报告来自浏览器生成的虚构简历，与两张用户图片的私有验收分开。修复前实现来自 Git HEAD：`55f93233eac04c82c6a2722d38c20f4c33aa9bd0`；验收没有切换工作区。

## 条件与指标

6 种字体/版式组合，各使用原尺寸 PNG 和缩小至约 72% 的 JPEG（质量 74），共 12 组。包含单栏、双栏、18/20/22 像素正文，使用本机系统字体。最后两种紧凑版式在第一轮调试后加入，用于暴露原样例未覆盖的问题。它们现在也属于回归集，不能继续称作全新的盲测。

字符准确率忽略空白，以浏览器 DOM 文本为真值；因此 100% 不代表空格、标点与原图完全一致。字体指标按文本块的候选字体是否命中生成时指定的字体统计，不是整张图的视觉相似度。完整验收还要求字号误差中位数 ≤12%、归一化位置误差均值 ≤1.5%、无漏块和无初始溢出。字体候选命中率须 ≥65%。

## 两张用户图片的私有验收

- 本次截图对应的图片：50 行文字、21 个几何对象（含恢复的灰色分隔线和列表圆点），编辑器与静态导出初始溢出均为 0。原来低置信度的长行通过局部复识别恢复；未复制源图或原头像为成品资产。
- 先前的另一张图片：单独保留私有对照和编辑/保存验收，不作为上述 12 组的组成部分，也不加入固定公共样例。
- 图像像素中仍有字体、局部粗体、空格和误读细节无法完全还原。对照通过与无溢出都不等于逐像素还原。

## 复现与边界

运行 `.\.venv\Scripts\python.exe scripts/verify_generalization.py --baseline --holdout`。完整逐块数据和生成图像在忽略版本管理的 `artifacts/generalization/corpus/`，用户图片验收在 `artifacts/generalization/user-current/` 与 `user-previous/`。后续 HEAD 变化会使 `--baseline` 的参照变化，本表保留上述提交的测量结果。

低分辨率、压缩、未知字体、复杂图标/背景与旋转仍需扩大真实授权样例验证。当前证据支持常见版式上的改进，不构成任意简历图都能自动还原的保证。
